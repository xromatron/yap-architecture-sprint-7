# Требования к внешней интеграции

## Общие требования к безопасности

1. Контроль доступа
   - должна использоваться многофакторная авторизация
   - использоваться минимально необходимые привилегии
2. Системы мониторинга и управления угрозами
   - должна быть установлена система мониторинга действий с алертами в случае подозрительной активности
3. Защита данных
   - всё взаимодействие должно осуществляться по зашифрованным каналам связи
   - предусмотрена возможность восстановления данных в случае их утери или повреждения
4. Соблюдение нормативных требований
    - использование шифрования при хранении персональных и биометрических данных
    - использование токенизации при взаимодействии с внешней системой

## Протоколы аутентификации и авторизации

1. аутентификация с использованием OAuth 2.0 или OIDC
2. авторизация:
   - пользователи имеют доступ только к своим данным
   - внешняя система имеет доступ ко всем данным без информации о принадлежности к конкретному пользователю

## Как будет организовано взаимодействие между системами предприятия и внешней платформой

1. взаимодействие по зашифрованным каналам связи с использованием JWT токенов, имеющих ограниченный срок действия
2. единая точка входа для всех внешних платформ для единообразного управления доступами
3. доступ внешней платформы возможен только к ограниченному сегменту сети
4. мониторинг всех взаимодействий с алертами в случае подозрительной активности
5. если хранение персональных данных будет осуществляться на внешней платформе, обязательно соблюдение законодательства РФ

## Новый сервис smart-devices-app
API сервиса для витрины:
- добавить биометрию: позволяет собственнику квартиры добавить себя и других лиц для возможности автоматического открытия
дверей в случае распознавания лиц
- удалить биометрию
- добавить номер автомобиля собственника для возможности автоматического открытия шлагбаума
- удалить номер автомобиля
- открыть шлагбаум - для возможности собственнику через приложение открыть шлагбаум для себя, в случае если он заезжает
на автомобиле, номера которого нет в базе, он грязный, необходимо запустить а/м доставки или скорой помощи

Партнеру передается лишь необходимая информация без привязки к конкретному собственнику:
- номер автомобиля, пункт пропуска
- биометрические данные, дом, подъезд
Таким образом даже если у партнера произойдет утечка данных, невозможно будет связать адреса или номер автомобиля 
с конкретными персональными данными
